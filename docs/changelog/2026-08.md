## New `casting_director` + a no-overlap pass over the shot-direction stack (2026-08-04)

User reviewed the intro-montage grid and named three concrete failures: a baby shower
rendered as the protagonist alone at home (should be a group event without her), prayer/
faith/desperation beats rendered with serene faces (should read as visible weeping), and
scene 1's quoted taunt by another person rendered as her alone (should show the speaker).
Tracing each to its owner surfaced that presence/casting was tangled inside the shot
authors. User's governing principle for the fix: **"there should be no overlap unless it's
a review — this breaks my mental model."** `PROMPT_CONTRACT_VERSION` 20 → 21;
`LOCATION_SCOUT_CONTRACT_VERSION` 3 → 4; `EMOTION_SCOUT_CONTRACT_VERSION` 1 → 2;
`RECOGNITION_DIRECTOR_CONTRACT_VERSION` 2 → 3; new `CASTING_DIRECTOR_CONTRACT_VERSION = 1`.

- **New `agents/casting_director`** — owns who-is-in-frame + how-a-crowd-is-staged-and-
  dressed, for EVERY beat. `character_ids` default to none/protagonist-only; another
  tracked character is added only when the beat singles them out by name/singular-ref/
  quoted speech (a plural collective noun never promotes a crowd into a named character);
  the protagonist is defaulted OUT of a shared occasion centered on someone else; a quote
  spoken AT her by an untracked person is staged two-person with the speaker in frame.
  Concrete beats cast from narration, abstract beats from world + emotional stakes only
  (they stay narration-blind, per the lane rule). Chunked-parallel, fail-open to
  protagonist-solo.
- **Both shot authors in `src/scene_engine.py` are now pure renderers.**
  `author_literal_beat` and `author_story_beat` no longer emit `character_ids` or decide
  presence — they receive `casting` and render exactly that cast + staging. `_shot_schema`
  drops `character_ids` when the author isn't casting. Also removed `author_story_beat`'s
  redundant `characters + visual_story.supporting_characters` merge — the supporting cast is
  already locked into `characters` (as director cast) by `run.py` before this point.
- **`agents/recognition_director` pulled back to PLACE/OBJECT anchors only.** The 2026-08-03
  version had been expanded to also propose people/attire anchors; once `casting_director`
  existed that overlapped its presence/staging call, so people were removed here — one
  concept, one agent.
- **`agents/location_scout`** gained a hard rule: a communal/social occasion (baby shower,
  wedding, party, funeral) goes to its real venue, never the protagonist's home, even when
  the narration only has her attending/thinking about it.
- **`agents/emotion_scout`** now scores prayer / deep faith / hope-against-silence / quiet
  desperation as overt weeping (visible tears, trembling face), never a serene prayer face.
- **Overlap trims:** occasion crowd-attire deleted from the authors (casting owns it via
  `staging_note`); the "give the space real-world scale and grandeur" re-instruction deleted
  from the authors' recognition line (location_scout owns venue scale).
- **`agents/CLAUDE.md`** gained operating-philosophy **rule 6 (one concept, one agent — no
  overlap except a review pass)** codifying the user's principle, plus a new standing rule
  documenting `casting_director`'s ownership and the recognition place/object-only scope.
- Validated with a fresh 20-scene grid harness: quote-by-others now stages the speaker in
  frame, prayer/faith/desperation render as visible weeping, a church wedding held one venue
  across 9 beats with the protagonist correctly OUT of the group beats and the recognition
  anchors place/object-only. `staging_note` is now on each scene payload but not yet surfaced
  in `web/` (same status as `location`/`recognitionCue`).
- **Follow-up (same day): "leave the protagonist out" hardened into an aggressive standing
  preference.** The first pass only dropped her from occasions *centered on someone else*; a
  lone montage line naming an occasion but framed as her watching it ("… while you stand
  still") kept her home alone. Per repeated user direction — *if there's an opportunity to
  not put the protagonist in a scene, always take it; she's in plenty of others* —
  `casting_director` (v1→2) now leaves her out whenever a beat can stand on an event, an
  occasion, other people, a place, or an object, even when phrased as her watching/attending;
  she stays only when the beat names her or is an inherently private interior moment of hers.
  `location_scout` (v4→5) matches: a plural/passing/montage mention of a communal occasion,
  or one framed as her merely watching, still gets that occasion's real venue, never her
  home. Prompt examples kept generic — no current-script phrasings hardcoded into any rule.

## Restructure into small, single-responsibility agents (2026-08-03)

User asked, distilled from the prior session's brief
(`scene-directing-next-session-brief.md`): break the pipeline into more small,
individually-diagnosable agents — "the reason we're using agents is so I can diagnose
without reading the actual code." Architecture and naming were locked in with the user
(`AskUserQuestion`) before any code changed. `PROMPT_CONTRACT_VERSION` 18 → 19.

- **`agents/visual_director` split into `agents/emotion_scout` + `agents/world_builder`.**
  That module bundled two judgments in one file (emotional-spine scoring, then
  worldbuilding) — now two files, each independently re-runnable. `emotion_scout` also
  gains two new per-beat fields, `emotional_stakes` and `expression_directive` — the
  categorical score alone was producing "too calm and collected" output (user's words: "if
  it's laughter, it should be bold... tears... a lot of hand-holding-the-head"); the
  categorical score never told a shot author to actually render that.
- **`agents/location_scout` extracted from `src/scene_engine.py`'s inline
  `assign_locations()`.** Same behavior, now its own diagnosable module. Also finally
  implements the grandeur-matching fix flagged but not built last session: a significant
  occasion (wedding, funeral, baptism, any ceremony) must get a location whose real-world
  scale and formality actually matches it — the prior bug held one location correctly
  across a run of beats, but that location could still read as a plain folding-chair room
  for what should have been "a very big church, a very glamorous location" (user's words).
- **New `agents/recognition_director`.** Given a beat's location + emotional stakes,
  proposes ONE concrete, real-world-scaled iconic visual anchor for significant occasions
  only (empty for ordinary/domestic beats) — feeds forward into `src/scene_engine.py`'s one
  shot-author call, which still writes the final `image_prompt` itself.
- **`agents/scene_compositor` renamed `agents/scene_renderer`** (user: didn't like the old
  name, wasn't sure what `visual_director` even did from its name either — both addressed
  in this pass). `COMPOSITOR_CONTRACT_VERSION` → `RENDERER_CONTRACT_VERSION`.
- **New `agents/recognition_reviewer` + `agents/drama_reviewer`.** Two narrow post-hoc
  passes over already-authored scenes. This is explicitly the "second LLM judges the first
  LLM's taste" pattern `agents/CLAUDE.md` rule 2 warns against — flagged to the user via
  `AskUserQuestion` (pre-pass-that-feeds-forward vs. post-hoc-rewrite-pass) before building
  either way; the user chose the post-hoc reviewer explicitly. Added a dated carve-out note
  to rule 2 documenting the exception and the narrow scope both reviewers are held to (may
  only ADD one concrete detail to an existing prompt, must return it unchanged verbatim
  when no change is needed, never re-author subject/action/characters/framing) — if they
  stop converging the way the rule predicts, the fix is pushing their judgment upstream
  into the pre-pass agents, not a third reviewer.
- Pipeline stage count went from 12 to 13 (`docs/architecture.md`) — REVIEW is new stage 7,
  shifting WARDROBE/IMAGES/ALIGN/RENDER/S3/CLICKUP each up by one.

Not done this pass: renaming anything further — the brief's own note says don't rename
twice, so names only got locked once the new agent boundaries were actually decided.

## Location continuity, protagonist-optional shots, confrontation staging, expression fidelity (2026-08-03)

Follow-up to the reference-video side-by-side comparison (`scene-directing-holy-grail.html`)
— four targeted prompt/architecture fixes to `src/scene_engine.py`, `PROMPT_CONTRACT_VERSION`
16 → 17 → 18, no new agent added (per `agents/CLAUDE.md`'s fix order: sharper prompt / more
targeted call before a new gate or agent):

- **Populate scenes without waiting for the script to say so, vary the protagonist's own
  action.** Both `author_story_beat` and `author_literal_beat` now explicitly instruct: infer
  when a location/occasion plausibly involves other people (a church, a wedding, a workplace)
  and show them as anonymous background even when the narration never says "a crowd was
  there"; give the protagonist a specific ordinary action (driving, cooking, shopping,
  jogging, working) instead of defaulting to sitting/standing whenever the beat allows it.
- **Location continuity (the scenes-15/16/17 "she magically came back to her house" bug).**
  New `assign_locations()` pre-pass: chunks narration snippets the same way
  `cut_narration_scenes` does, and asks one LLM call per chunk to assign one location string
  per snippet, in order, holding it fixed across a run of beats describing the same
  continuous event. Both author functions now take a `location` arg and must honor it rather
  than picking freely per-beat with zero memory of the immediately preceding beat.
- **Protagonist-optional literal beats.** Explicit permission: if the narration's actual
  subject is someone/something else (a wedding couple, another character, an object), a shot
  can be entirely about that — she does not have to be forced into every scene just because
  she's the throughline.
- **Confrontation staging for untracked speakers.** When a snippet is a quoted line spoken TO
  the protagonist by someone not in TRACKED CAST, stage it as a two-person moment (that
  speaker as an anonymous foreground figure) instead of showing her alone reacting to an
  unseen voice — this was the exact gap in our scene 1 vs. the reference's opening.
- **Expression fidelity.** Both prompts now require any visible face to actually read the
  beat's own `emotional_valence`/`story_pressure` (strain/longing/tears for low valence,
  tension for high pressure) instead of defaulting to a pleasant resting expression.

Not built: a separate "dramatic director" review-pass agent (birds-eye pass across a batch of
already-planned shots) — flagged in the holy-grail doc as a bigger lift, left for explicit
opt-in rather than built speculatively.

Validated by rerunning the disposable `sample20_hannah.py` harness (fresh Hannah script/cast,
cached to avoid re-paying for dossier/characters) for a third time on top of the population/
camera-variety fixes already applied.

## Removed the invented parallel plot; camera-framing variety (2026-08-03)

### Problem: job 2158's abstract-mode scenes fought the narration

User review of `/job/2158`'s output: `agents/visual_director` was inventing a fully
independent standalone plot (`parallel_story`/`external_goal`/`protagonist_arc`,
authored sequentially with its own recap/location-tally continuity, per beat) that
kept diverging from the narration's real arc — "a constant fight." Root cause of the
protagonist going missing from scenes that should show her: `scene_engine.py`'s
abstract-mode shot planner (`author_story_beat`) had its `character_ids` schema enum
hard-capped to whatever cast the earlier invented-plot beat had already assigned —
if that beat cast supporting characters instead of the protagonist, the shot could
never add her back. (Literal/concrete-mode beats never had this bug — they've always
used the full tracked cast.)

### Fix

- **`agents/visual_director/client.py`**: dropped `parallel_story`/`external_goal`/
  `protagonist_arc`/`story_beats` and all of the sequential beat-authoring machinery
  (`_beat_chunk_schema`, `_author_beat_chunk`, `_author_story_beats`, `_recap`,
  `_location_tally`, `_validate_bridge_cues`) — two passes now instead of three:
  emotional spine, then one world-bible call (`film_title`/`movie_style`/
  `supporting_characters`/`recurring_locations` only, no plot to resolve).
  `VISUAL_STORY_CONTRACT_VERSION` 13 → 14.
- **`src/scene_engine.py`**: `author_story_beat` no longer receives a pre-cast
  `story_beat` — it works directly off the shared world bible + this beat's own
  emotional-spine entry, with the full world cast (protagonist included) always
  available, same pattern `author_literal_beat` already used. `break_into_scenes`
  now dispatches exactly one author per beat by `visual_mode` (concrete → literal,
  abstract → world) instead of always running both and discarding one — the
  "keep the parallel author warm across beats" reason for running both evaporated
  once there's no cross-beat plot state to keep warm. `_pick_shot` deleted.
  `PROMPT_CONTRACT_VERSION` 12 → 13.
- **Camera framing variety** (user ask, same session): `camera_distance`'s
  categorical field (scored in the emotional spine) was computed but never actually
  read by any shot-authoring prompt — dead output. Extended its enum from
  `wide/medium/close/varied` to `wide/medium/close/macro/pov`, and both shot authors
  now inject an explicit framing instruction per beat (`_CAMERA_GUIDANCE`/
  `_camera_instruction` in `scene_engine.py`) — macro for object/gesture-carried
  beats, pov for beats about noticing/fixating on something.
- Trimmed downstream references to the removed fields: `src/run.py`'s post-director
  log line, `agents/character_ledger/client.py:build_director_cast`'s `film_handoff`.
- `tests/test_agent_contracts.py`/`tests/test_two_lane_story.py` updated for the
  removed `story_beats`/`_pick_shot`/`_validate_bridge_cues` surface.

### Verified

`python3 -m py_compile` on every touched file; full `python3 -m unittest discover -s
tests` (17 tests) green; `agents/visual_director/client.py`'s own self-test passes.
No live LLM self-test run (costs real API money) — next real validation is the
user's own fresh `/ingest`.

## Character wardrobe variants + human approval gate (2026-08-02)

### Problem: story-coherence review of a full 105-scene render (job 2158)

User asked for a full-image coherence review of a finished job (`/job/2158` on the
deployed production UI). Fetched the job payload directly (`GET /jobs/{row_id}` via
`web/app/api/proxy`, `x-ingest-secret` header) rather than screen-scraping the
client-rendered Next.js page, downloaded all 105 scene images + 6 character reference
sheets, and fanned out 7 parallel review agents (15 scenes each) checking each image
against its character reference sheets and its own narration/imagePrompt.

Two classes of finding, 35/105 scenes flagged:

1. **A duplicate-identity bug in the character ledger.** The narration's one protagonist
   (addressed as both "the protagonist" and, later in the same script, "Ellen") got split
   into two competing tracked characters — `protagonist` (White, 51) and `ellen`
   (Hispanic, 49) — used inconsistently scene-to-scene, including the film's own final two
   scenes (103→104, the same continuous birthday-morning moment) showing two different
   women back to back. Root-caused but **not fixed this phase** — a `character_ledger`
   dedup problem, separate from the wardrobe work below.
2. **Wardrobe never changes for context.** Every character has exactly one full-body
   reference image, reused as i2i conditioning in every scene regardless of setting — a
   woman in an everyday field jacket at a formal wedding, when the narration says "she
   wore the green dress." This IS what got fixed this phase.

### Fix: `agents/character_wardrobe` + a hard pipeline gate

User's own design, refined into an implementation plan (`EnterPlanMode`/`ExitPlanMode`,
approved) before touching code:

- **New agent, `agents/character_wardrobe/client.py`** — one whole-film schema-locked
  LLM call (not chunked; wardrobe is a global decision per `agents/CLAUDE.md` rule 4)
  deciding, per tracked character, which SIGNIFICANT recurring contexts (a wedding, a
  work uniform) need their own outfit variant — everyday scenes keep the base reference.
  Deterministic `_validate()` fact-check: every `scene_number` assigned to a character's
  variant must be a scene where that scene's own `character_ids` actually includes them
  (the schema can't express this cross-field constraint, so it's the one real Python
  check, per rule 3). Retry-with-feedback loop, same shape as `character_ledger.build()`.
- **`agents/character_sheet/client.py`** gained `generate_variant_one`/
  `generate_variants_all` — i2i off the character's own base reference (same mechanism
  `scene_compositor` already uses), and `generate_one`/`generate_variant_one` both take an
  optional `prompt=` override for the production UI's regenerate route.
- **`agents/scene_compositor/client.py`** — `compose_one` now resolves a per-scene
  wardrobe variant when the scene calls for one (`_variant_lookup`, inverted once from
  each variant's `scene_numbers`), falling back to the base reference if that variant's
  image isn't ready. Returns `character_refs_used` (which reference each present
  character actually resolved to) for the production UI's per-scene audit display.
- **The gate**: `src/run.py`'s `prepare_pipeline` split into `prepare_cast_and_scenes`
  (stages 1-7 + wardrobe, ends at a new `awaiting_wardrobe_approval` status) and
  `prepare_images_and_align` (stages 8-9). `src/ingest_server.py` reuses its existing
  single ingest queue/worker with a `phase` tag instead of adding a second queue; new
  route `POST /jobs/{row_id}/approve-wardrobe` flips status + resumes. Crash-resume tells
  the two `preparing` sub-phases apart via a `wardrobeApprovedAt` payload marker (same
  "payload flag as gate" idiom `renderUrl`/`clickupPushedAt` already use). CLI
  (`python3 src/run.py <row_id>`) still auto-approves by default — only the
  production/UI path (`ingest_server.py`, which never calls `run_pipeline`) hard-pauses.
- **Web UI**: new `awaiting_wardrobe_approval` job status/section. `CharacterModal.tsx`
  (new) — click any character/variant thumbnail, opens a big-viewer + thumbnail-strip +
  full-editable-prompt modal (mirrors `SceneModal`'s existing UX), Regenerate button.
  `CharacterWardrobeReview.tsx` — per character, a `flex-wrap` thumbnail row (base +
  every variant, all visible, no scroll-clipping) that opens the modal; one
  "Approve & Generate Scene Images" button. Per-scene audit badges (grid card +
  `SceneModal`) resolve `character_refs_used` ids to human-readable names/context labels
  via `resolveCharacterRefsUsed()`, disambiguating a name collision (two characters can
  both be "Samuel") by appending the character's `role`.

### Bugs found during the user's live local test (before any deploy)

- **Body build drifted between a character's variants.** `build_variant_reference_prompt`
  originally sent only the outfit text + a generic "same face/build as the reference
  image" instruction — no concrete text backing it, so gpt-image-2's i2i edit drifted.
  Fix: `agents/character_ledger.compile_identity_profile()` (new — same fields as
  `compile_visual_profile`, minus clothing) is now concatenated into every variant prompt,
  anchoring age/height/build/face/hair as explicit text alongside the reference-image
  conditioning.
- **Regenerating a variant silently dropped the style/identity framing.** The UI only
  ever showed/edited the bare compiled clothing sentence (`outfit_prompt`); the actual
  full prompt (style scaffold + identity + outfit) was invisible and, worse, a human edit
  went out as the WHOLE prompt with no re-wrapping — losing the Pixar-style/identity
  framing entirely on any edited regenerate. Fix: both `generate_one` and
  `generate_variant_one` now always compute and return `reference_prompt` (the exact
  full string used, success or failure), stored on the character/variant and shown as the
  editable default in the UI — what you see is what gets sent, no hidden gluing.
- **UX**: original inline design (always-open textarea per thumbnail, `overflow-x-auto`
  row) read as "only the first variant visible, needs expanding." Replaced with a
  per-character modal (see above); the inline row is now thumbnails only (`flex-wrap`,
  always fully visible).
- **Not a bug**: a report of missing per-scene audit badges turned out to be the job
  still mid-`compose_all()` (`generating…` placeholders, no active image on any scene
  yet) — badges correctly have nothing to resolve until a scene has an active image.

### Verified

variant prompt and the character's OLD outfit text is not. `npx tsc --noEmit` and
`npx eslint` both clean across every touched web file.
